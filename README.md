# production-suite-budget-ai

> **ALL DATA IN THIS REPOSITORY IS SYNTHETIC.** It is generated by a seeded,
> documented simulation and contains no real customer, vendor or event data.
> Results on this data are not evidence of real-world predictive accuracy.

An academic project for *AI Development & Collaboration: Industry-Simulated AI
Product Workflow*. The business problem is **predicting budget overruns for event
productions**: will a production exceed its client-approved budget, with what
probability, and by how much (signed, in ILS)?

This repository is separate from any commercial product codebase. It contains
only original code, synthetic data and documentation.

## P2 deterministic quality gate

The local, offline gate validates raw source files and a Crew-1 handoff (`clean_data.csv` + `dataset_contract.json`) before any downstream flow consumes it. Every expected value is rebuilt from the raw export under Policy C; groups and folds come from the frozen reference [`contracts/frozen_split.json`](contracts/frozen_split.json). Run `python -m gate.run --stage source --raw data/synthetic/v2/raw --out <output-dir>`; the handoff stage also requires `--data` and `--contract`. See [`docs/quality_gate.md`](docs/quality_gate.md).

## P3 Crew 1: the data-analyst crew

A CrewAI crew (`crew1/`) of three agents turns the raw export into the Crew-1 handoff:
- a Data Ingestion & Cleaning Engineer;
- an Exploratory Data Analyst;
- a Data Contract & Insights Author.

The handoff is `clean_data.csv`, `dataset_contract.json`, `eda_report.html` and `insights.md`.

**Every value, Policy C transformation, statistic and contract field comes from deterministic Python tools; the agents choose the tools and write interpretation text only.** The crew works in an isolated workspace outside the repository and uses logical dataset names, never paths.

Post-run validators re-check every output: a byte-identical recomputation, the P2 gate, and quantitative claims against the computed statistics with units.

Install the pinned dependencies with `.venv\Scripts\python -m pip install -r requirements-crew.txt`. A live run (`python -m crew1.run --live --out artifacts/crew1/<run_id>`) needs `ANTHROPIC_API_KEY` in the environment; without `--live` or the key it exits `2` and makes no call. The offline tests need no key and block the network. See [`docs/crew1.md`](docs/crew1.md).

## The dataset (seed 42, active version v2)

**The versioned synthetic dataset under `data/synthetic/` is committed intentionally as the project's source data.** It is regenerable byte-for-byte from the seed, and a test checks the committed copy against a fresh generation. `v1` is kept frozen for traceability; `v2` is active ([`docs/target_audit.md`](docs/target_audit.md)).

| | |
|---|---|
| Productions | **400** (4 archetypes × 100) |
| Snapshots per production | **4** (S0 contract · S1 35% of lead time · S2 65% · S3 14 days before the event) |
| Snapshot rows | **1,600** |
| Split (by production) | train 280 · test 80 · demo 40 (1,120 / 320 / 160 rows) |
| CV folds | 5, on train only, grouped by production |
| Overrun rate | 47.2% of snapshots |

## Target

```
budget_gap_ils = final_cost_pre_vat + (contractual fee, if included in the budget) − approved budget   (pre-VAT, signed)
is_overrun     = budget_gap_ils > 0.5   (any positive excess; 0.5 is rounding tolerance only)
```

- A 2% materiality level exists only as a warning flag.
- A later fee concession changes company profit, never the overrun label.
