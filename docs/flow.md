# P5: the end-to-end CrewAI Flow

> **ALL DATA IS SYNTHETIC.** The CrewAI Flow, both Crews, their Agents and Tasks run for real
> (`crew.kickoff()` inside Flow methods). **The LLM responses are scripted**: an in-process transport
> (`crew_common/scripted.py`) answers every model request from a fixed script. No model inference takes
> place, no request leaves the process, and no API key is needed. Every scripted text starts with
> `[SCRIPTED RESPONSE - not LLM inference]`. Every number, check, fit and artifact is computed by
> deterministic Python tools.

## Install (fresh clone)

Python 3.13, a separate virtual environment (the pinned reference environment of the approved results is
Windows AMD64 with the versions in `requirements-ml.txt`):

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-ml.txt
```

Nothing outside the clone is needed: the raw synthetic export (`data/synthetic/v2/raw/`), the frozen split,
the approved Crew 1 handoff (`artifacts/crew1/p3-live-005/`) and the pinned P4 reference
(`budget_flow/contracts/`) are committed. Local P3/P4 run folders (`out/`) are not used.

## Run

| Purpose | Command | Expected status (exit code) |
|---|---|---|
| Normal end-to-end run | `.venv\Scripts\python -m orchestrator.flow --out out/flow_runs/run-001 --n-jobs 5` | `PASS` (0) |
| Column rename | `... -m orchestrator.flow --out out/flow_runs/break-rename --scenario column_rename` | `STOPPED_CONTRACT` (3) |
| Money unit x100, matching contract regenerated by the attacker | `... --scenario money_x100` | `STOPPED_CONTRACT` (3) |
| Required snapshot row deleted from `clean_data.csv` | `... --scenario row_deletion` | `STOPPED_CONTRACT` (3) |
| Required column definition deleted from `dataset_contract.json` | `... --scenario contract_column_deletion` | `STOPPED_CONTRACT` (3) |
| Outcome label leaked as an input column | `... --scenario label_leakage` | `STOPPED_CONTRACT` (3) |

Every run needs a new, empty `--out` folder. A normal run takes about 5 minutes with `--n-jobs 5` (the 9
pre-registered grouped-CV runs are not shortened); a stopped run takes under a minute, because Crew 2 never
starts. `FAILED_RUNTIME` (1) means a runtime error, never a completed model run.

## The Flow (`orchestrator/flow.py`)

| Decorator | Method | Does |
|---|---|---|
| `@start()` | `run_crew1` | Crew 1 kickoff (3 agents) -> `crew1/`: `clean_data.csv`, `eda_report.html`, `insights.md`, `dataset_contract.json` |
| `@listen(run_crew1)` | `prepare_handoff` | copies THIS run's `clean_data.csv` and `dataset_contract.json` to `handoff/`, writes their `flow_contract.json` (flow-1), then applies `--scenario` to that copy only |
| `@router(prepare_handoff)` | `contract_gate` | flow-1 validation of `handoff/`; routes `PASS`, `STOPPED_CONTRACT` (with violation codes) or `FAILED_RUNTIME`; any gate exception stops the run (fail closed) |
| `@listen("PASS")` | `run_crew2` | Crew 2 kickoff (3 agents, TRAIN-only) on `handoff/` only -> `crew2/`: `features.csv`, `model.joblib`, `evaluation_report.md`, `model_card.md` |
| `@router(run_crew2)` | `verify_outputs` | `COMPLETE` when all 8 required outputs exist and TEST stayed sealed, else `FAILED_RUNTIME` |
| `@listen("COMPLETE")` / `@listen("STOPPED_CONTRACT")` / `@listen("FAILED_RUNTIME")` | `finish_pass` / `stop_on_contract` / `record_failure` | the run status |
| `@listen(or_(finish_pass, stop_on_contract, record_failure))` | `write_manifest` | closes the run |

The run folder holds `flow_manifest.json` (status, routes, gate decision and violation codes, both crews'
kickoff evidence, input and output hashes, selected model, timing) and `flow_events.jsonl` (the Flow's own
lifecycle events from CrewAI's event bus). Each crew folder holds its `crew_kickoff.json` (CrewAI events,
scripted exchanges, Python tool calls) and `trace.jsonl`.

## Boundaries

* Crew 2 reads only `handoff/` (a runtime guard refuses the raw export, Crew 1's code and `crew1/` during the
  Crew 2 stage); its code never imports Crew 1.
* TEST is never reopened: the test vault is sealed, W3, `Session.run_all`, `evaluate_on_test_once` and
  `TestVault.open` are never called, and the historical P4 TEST result is cited from the pinned reference.
* The deliberate breaks change only the Flow's `handoff/` copy; Crew 1's outputs and all committed evidence
  stay unchanged (their hashes are recorded before and after).
