# The complete Flow with a live LLM

> **ALL DATA IS SYNTHETIC.** A live run sends synthetic data only (the generated raw export, statistics and
> tool results) to the Anthropic API. Nothing in it is real customer, vendor or event data.

By default the Flow uses **scripted** model responses: the CrewAI Flow, both crews, their six agents and tasks
run for real, but an in-process transport answers every model request from a fixed script (no inference, no
network, no key). This keeps the regression tests reproducible byte for byte.

With `--llm live` the **same Flow, the same six agents, the same tools and the same deterministic contract gate**
run with responses generated by the Anthropic API (`claude-haiku-4-5-20251001`). This page explains what changes,
how to run it, how to verify it from the files alone, what it costs and how to handle the API key.

## What changes in live mode, and what does not

| | scripted (default) | live (`--llm live`) |
|---|---|---|
| CrewAI Flow, 2 crews, 6 agents, 6 tasks, `crew.kickoff()` | real | real |
| Who decides which tool to call and writes the narrative | a fixed script | the model (`claude-haiku-4-5-20251001`) |
| Data, statistics, charts, contract, features, CV, model selection, fit, reports | deterministic Python tools | deterministic Python tools (unchanged) |
| Contract gate between the crews | deterministic Python (`budget_flow/handoff.py`) | the same code |
| Crew 2 starts | only on the gate route `PASS` | only on the gate route `PASS` (plus an explicit check of the recorded decision) |
| Network | blocked | `api.anthropic.com` only; any other host is refused |
| Evidence of model calls | scripted exchanges, marked `[SCRIPTED RESPONSE - not LLM inference]` | one record per provider call (below) |

There is **no fallback**: in live mode the scripted transport is never installed. A provider error, a budget
overrun or an agent that never got a live response fails the run (`FAILED_RUNTIME`, exit 1); it is never reported
as `PASS`.

The model only chooses tool calls and writes text. It cannot change a number: Crew 1's handoff is recomputed and
checked by its own gate, the Flow's contract gate validates the handoff, and Crew 2's selection rule, refit and
reproduction check against the approved P4 run are code. So a live run is expected to select the same model
(logistic regression, `C = 10`) as the scripted run. The narrative texts and `dataset_contract.json`'s column
descriptions are written by the model and differ between runs.

## Provider-call record

`crew_common/live.py` (`RecordingTransport`) sits at the httpx transport layer, where the scripted transport sits
in the default mode. It forwards each request unchanged and records, per call, **no header and no body**:

| field | meaning |
|---|---|
| `crew`, `agent` | `crew1` or `crew2`; the agent, identified by the tools offered in the request |
| `started_utc`, `finished_utc`, `seconds` | when the call was sent and answered |
| `status` | the HTTP status from the provider |
| `provider_request_id` | Anthropic's `request-id` response header |
| `message_id`, `model`, `stop_reason` | from the provider's response (`msg_…`, the model that answered) |
| `usage` | input, cache and output tokens reported by the provider |
| `tool_calls` | names of the tools the model asked for |
| `request_sha256` | a digest of the request body (not the body) |

The records are in `crew1/crew_kickoff.json` and `crew2/crew_kickoff.json` under `llm_transport.exchanges`. The
totals, the estimated cost and the budget are in `flow_manifest.json` under `llm`. UTC times of the Flow steps
(`crew1_started`, `gate_decided`, `crew2_started`, …) are under `timing.utc`, and every Flow event in
`flow_events.jsonl` carries a `utc` field.

## Controls

| control | value | where |
|---|---|---|
| Requests per Flow (SDK retries included) | at most 150 (expected about 45) | `crew_common/live.py` `DEFAULT_BUDGET` |
| Input tokens per Flow | at most 2,000,000 (expected about 350,000) | same |
| Output tokens per Flow | at most 150,000 (expected about 30,000) | same |
| Output tokens per response | 8,192 | `LLM_SETTINGS` (Crew 1 and Crew 2) |
| Temperature | 0.0 | `LLM_SETTINGS` |
| SDK retries per request | 2, timeout 180 s | `LLM_SETTINGS` |
| Requests per minute | 20 per agent and per crew | P3 `CREW_MAX_RPM`, Crew 2 `LIVE_MAX_RPM` |
| Model turns per agent | Crew 1: 12 / 18 / 10; Crew 2: 6 / 20 / 8 | `AGENT_LIMITS` |
| Agent retries of a whole task | 0 | `AGENT_MAX_RETRY_LIMIT` |

A request over the Flow budget is refused before it leaves the process and the run fails. The worst case
allowed by the budget is about **USD 2.75** per run (2M input tokens at USD 1 per million plus 150k output
tokens at USD 5 per million).

## Run it

From a fresh clone (Windows, Python 3.13; on macOS/Linux use `python3.13 -m venv .venv` and `.venv/bin/python`):

```
git clone https://github.com/yuvalipa-dotcom/production-suite-budget-ai.git
cd production-suite-budget-ai
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-ml.txt
```

Set the key for this terminal only (input hidden, nothing written to disk or history):

```
# Windows PowerShell
$k = Read-Host "Anthropic API key" -AsSecureString
$env:ANTHROPIC_API_KEY = [System.Net.NetworkCredential]::new("", $k).Password
Remove-Variable k
```

```
# macOS / Linux
read -rs ANTHROPIC_API_KEY && export ANTHROPIC_API_KEY
```

Run the complete Flow once:

```
.venv\Scripts\python -m orchestrator.flow --llm live --out out/flow_runs/live-001 --n-jobs 5
```

Then verify the run from its files, and clear the key from the terminal:

```
.venv\Scripts\python -m orchestrator.verify_live_run out/flow_runs/live-001
Remove-Item Env:ANTHROPIC_API_KEY          # macOS / Linux: unset ANTHROPIC_API_KEY
```

Without the key the live command exits `2` and makes no call. Each run needs a new, empty `--out` folder.

## Verify it

`orchestrator/verify_live_run.py` uses the standard library only (no CrewAI, no network, no key) and exits `0` only when
every check passes:

| check | what it proves |
|---|---|
| L1 | the Flow finished `PASS` (exit 0, no error) in live mode |
| L2 | the Flow routed Crew 1 → handoff → gate `PASS` → Crew 2 → output check `COMPLETE` |
| L3 | the deterministic gate returned `PASS` with 0 violations, on exactly the files in `handoff/`; no deliberate break |
| L4 | all 8 required outputs exist and match their recorded sha256 |
| L5 | every exchange is a recorded live Anthropic call (status, `request-id`, `msg_…` id, `claude-…` model, usage) |
| L6 | each of the six agents received at least one successful live response; CrewAI executed 6 agents |
| L7 | no scripted response anywhere in the run |
| L8 | by UTC time: every Crew 1 call finished before the gate decision; the gate decided `PASS` before Crew 2 started; every Crew 2 call started after that |
| L9 | the manifest's call and token totals equal the recorded exchanges |
| L10 | no API key in the evidence |

The eight required outputs:

| Crew 1 (`crew1/`) | Crew 2 (`crew2/`) |
|---|---|
| `clean_data.csv` | `features.csv` |
| `eda_report.html` | `model.joblib` (a pickle: load it only from this verified repository, after checking its sha256) |
| `insights.md` | `evaluation_report.md` |
| `dataset_contract.json` | `model_card.md` |

The verifier proves consistency of the files; it cannot prove by itself that a file was not fabricated. The
independent checks are: the provider's usage page for the key's workspace shows requests at the recorded UTC
times (it aggregates all use of the workspace, so it is not an itemized bill for one run); and anyone with a key
can produce a new run and verify it.

The offline test `tests/test_flow_live.py` runs the whole live path with a stand-in for the provider behind the
recording transport (identifiers `msg_offline_test_*`). The verifier passes every check on it **except L5**,
which rejects those identifiers. A scripted run fails L1, L5 and L7.

## The API key

Use a dedicated, temporary key for this demonstration only.

1. In the Claude Console (console.anthropic.com), create a separate **workspace** for the demonstration and set its
   **spend limit**. Optionally lower its rate limits.
2. Create an API key **in that workspace**, named for its purpose and its end date.
3. Share it privately (a direct message, never a channel, an issue, a commit or a screen recording). Treat any
   key that was ever shown on screen or pasted publicly as compromised: delete it and create a new one.
4. Set it only as the environment variable `ANTHROPIC_API_KEY` in the terminal that runs the Flow (above). Never
   put it in a file in the repository, a `.env` file that could be committed, or a command line that is saved in
   history.
5. **Revoke it** when the demonstration ends: Console → API keys → the key → delete (or disable). A deleted key
   stops working at once; runs in progress then fail with an authentication error.
6. **Monitor use**: Console → Usage and Cost, filtered by the demonstration workspace and key. Usage can appear
   with a delay.

The workspace spend limit is a **monthly limit for the whole workspace**, not a limit per key and not a 14-day
limit, and it may be enforced with a short delay. To bound a sharing period (for example 14 days), delete the key
at the end of the period (set a calendar reminder); to bound spending per run, rely on the Flow budget above.

The code never reads the key itself: only the Anthropic SDK does, through the environment. The trace recorder
redacts the key's value if it ever appears in a text, the provider-call record holds no header, and the verifier
(L10) and the pre-publication scan look for key material in the evidence.
